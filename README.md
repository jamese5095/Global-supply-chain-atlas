- BG区域页不展示案例依据栏目；全球页的案例依据与各行业页的案例内容保留。

地图热度采用浅蓝至深蓝分级，BG与六行业共用配色；无资料仍用灰色，国家选中及悬停使用蓝色。

## 统一数据工作簿（M0／M1）

编辑主目录为本Git工作副本。`data.json`保留已清理的六行业事实；`input/`是未改写的原始备份，不能直接覆盖主数据。`unified-workbooks/`中的六份统一数据版由主数据导出，与当前事实逐字段往返一致。

统一版保留主表版式和来源超链接，辅助工作表`_atlas_meta`存储稳定项目ID、明确地域与时间状态。它默认隐藏；不要删除。少量不能放入国家矩阵的全球项目在可见的“区域共用与全球项目”表中，避免虚构国家落点。辅助数据没有替代可见编辑：导入会检查所有可见单元格、真实链接与合并范围；C／D列、客户名称、项目标题和说明、来源标题与链接变化均重新解析。项目单独改名保留ID，空白国家格可新增带来源项目，清空项目格可删除其内容。

表头、客户行结构、工作表结构和合并范围变化目前明确拒绝自动载入；同时增删项目并改名、导致对应关系不明时也拒绝。原数据不被覆盖，文件中的新内容保留。此类结构调整应先更新模板后重导出。项目时间和承接范围不因标题改名而被年份关键词重新推断。不可见辅助表不是加密或敏感资料保管设施。

导入预览列出客户／记录／来源的新增、删除和修改数量。已知旧原件精确匹配时仍迁移至清理版；在旧原件上新增编辑且包含已撤下内容时，列出冲突并暂停覆盖，保留用户修改。资料备份恢复也检查已清理来源回流。后续新增有证据的项目不应通过恢复被撤下的旧ID实现。

### 命令行

```bash
# 默认只读预览，保存差异报告，不改data.json
node refresh-data.cjs "统一表格.xlsx" "高科技" --report "review.json"
# 通过完整校验和冲突检查后，输出独立候选bundle
node refresh-data.cjs "统一表格.xlsx" "高科技" --output "candidate.json"
# 明确应用到当前工程的主数据，失败不会部分替换
node refresh-data.cjs "统一表格.xlsx" "高科技" --apply
# 只读测试，输入目录是六份统一工作簿所在目录
node tests/workbook-roundtrip.cjs "unified-workbooks" "roundtrip-report.json"
```

`--apply`和`--output`不能同时使用。请在应用前保留备份；工具默认不写入主数据。

### 再次导出

表格作者使用工作区提供的`@oai/artifact-tool`，从原始参考表保留样式并重填主数据。SheetJS只用于读取和应用内解析。作者运行时应从宿主加载依赖，不往工程安装额外版本。

```bash
node tools/export-workbooks.mjs "导出目录" "高科技"
# 省略行业名时导出全部六行业
node tools/export-workbooks.mjs "导出目录"
```

导出依赖Artifact Tool作者运行时与Python 3标准库。公开作者API未提供的原生超链接关系、交换格式标识、辅助表隐藏及双向冻结，通过`tools/finalize-workbook.py`定点补充OpenXML；单元格内容、样式、合并及布局由Artifact Tool生成。所有输出再用实际应用的读取器验证，防止导出成功但链接不可用。

本轮只建立统一数据和导入导出闭环，不改变现有区域顺序、业务分类或计数口径。145个客户条目、522条原始记录、589条来源及BG486项案例的基线保持。后续统计和分类改动按工程指南M2以后推进。工程校验及真实浏览器检查结果见`roundtrip-report.json`和交接进度。

## 外部承接商统计图（2026-10-26）

BG全球页TOP10、BG区域页TOP5；六个行业仅在各自全球首页展示TOP5，区域、国家、子行业和客户页隐藏。沿用已有业务类型选择，不新增筛选菜单。色块悬停或键盘聚焦可查看客户、项目及时间状态。业务类型筛选在此图按**主业务类型**生效；原业务结构图仍为多标签计数。

统计来源于当前六行业数据，独立于原地图统计。一个服务商承接一个案例只计一次；多承接商同一案例分别计入。每个“承接商—案例”只选一个官方业务类型，保障分段加总等于柱长。自营、集团内部物流、技术／设施供应商排除；未知主体或无法确认项目归属／主类型的内容不进入排名。统计反映收录资料中的承接案例数量，包含历史及规划，不代表市场份额或现有合同量。

当前135个案例符合统计条件，形成167条承接商—案例关系，涉及50家外部承接商。原BG486项案例、六行业事实与来源均未改写。少数既有区域条目与国家条目实为同一运营网络，统计层通过明确caseKey去重（ZF欧洲生产网络、乐高Tessenderlo RDC、Adidas Mantova）。区域与跨区域／全球范围保持原始披露，不复制到国家。

- `provider-core.js`：别名归并、内部主体排除、证据与签名校验、单主类型、去重与排名。
- `provider-policy.json`：经核对的别名及明确项目关联。客户D列汇总不能自动分摊给其所有国家项目；这里保存逐项确认的关联。项目文本、范围、来源或承接商职责改变时旧关联失效，需复核。新导入的已知主体、来源明确且仅一个官方类型的项目可直接计入；新增主体／多类型项目需要补充政策。
- `tools/build-provider-policy.cjs`：重建当前政策。修改主数据后须先复核关联，不能靠重建脚本自动证明新事实。
- `provider-ui.js`、`provider.css`：BG与行业复用的堆叠条形组件。
- `node tests/provider-ranking.cjs`：覆盖自营排除、别名去重、项目归属变更、17类限制、排名范围及分段合计。

归并遵循已核实主体关系：DHL各服务品牌与Deutsche Post统一；CEVA的旧Bolloré名称统一；输入中的Schenker（DSV集团）名称统一；GXO与Wincanton统一。HAVI与Martin Brower仍按披露运营品牌分别统计。GXO归并依据：[2024年完成收购公告](https://investors.gxo.com/news-releases/news-release-details/gxo-completes-acquisition-wincanton)、[2025年年报中的监管及整合说明](https://www.sec.gov/Archives/edgar/data/1852244/000185224426000007/gxo-20251231.htm)。其余项目依据保留在原数据与关联层的sourceIds中。

BG区域页的供应链业务结构仅展示案例数大于0的类型，右侧六行业数量完整保留（含0值）；全球页继续保留官方17类。此调整仅影响显示，不修改统计及数据。
