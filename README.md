# 头部企业国际供应链布局 · 六行业版

在线访问：[六行业供应链布局看板](https://jamese5095.github.io/1023-6/)

通过 GitHub Pages 从 `main` 分支根目录发布，首页为 `index.html`。

## 查看

打开 `index.html`，无需联网加载地图或表格读取组件。`page.html` 是构建模板，预览成品请使用 `index.html`。内置高科技、汽车、工业设备、消费品、医药、餐饮六个行业，来源为随附六份最新版XLSX。高科技、汽车、工业设备、消费品各25家客户，医药30家、餐饮15家，共145家客户。医药、餐饮使用2026年10月23日信源收敛后的工作簿，分别保留133和70条来源链接。点击页首行业按钮即可切换，无需重新打开网页。

- 一个页面保留三域联动：左侧客户，中间地图区域，上方官方17类业务筛选。
- 点击区域，右侧先按国家分组，再展示各客户的案例，不必先点击国家。点击地图国家或案例国家标题可进一步筛选。区域共用和跨区域案例单独展示。
- 选择客户，在地图下方展示全球生产、产能分工和需求市场摘要，地图位置不变。
- 标签栏固定高度，点击浅蓝边框按钮“清除选项 · 返回首页”清空客户、子行业、业务类型、区域、国家及客户搜索，返回全球总览。
- 全球与区域地图均不显示常驻地名、数量或方框，也不显示背景网格；鼠标悬停区域或国家显示名称、客户数、案例数和主要业务。区域与国家图形均禁用浏览器焦点外框。
- 承接主体、服务分工和来源保留在案例详情及客户信息中，不作为独立筛选维度。
- 删除三视角页签、业务矩阵、热度指标切换、资料范围和历史状态开关、布局背景切换及承接方筛选。
- 历史案例及规划以标记保留，境内参考不进入默认地图。制造配套单独标记并默认展示，可收起长列表。

国家选中仅加深填色，禁用地图图形的浏览器焦点外框；键盘焦点使用填色提示。没有资料的国家保留底图；切换客户或业务后，自动清除不再有案例的国家选择。区域合并信息集中展示，不复制为国家项目。跨区域和全球信息独立保留。

选中客户后，蓝点自动标记C列明确提及的生产／供给国家或区域，不标示工厂地址，不参与项目热度与数量统计。完整需求市场表述及来源保留在客户布局摘要中。

## 更新资料

点击页脚“资料管理”内的“更新行业表格”，选择最新版行业模板的XLSX，核对行业名称和导入摘要后保存。同名行业整体替换，其他行业保留。文件名符合“国际业务热力图_行业_版本.xlsx”时会识别行业名称，也可手动填写。

导入由本机浏览器完成，不上传工作簿。支持IndexedDB的环境会持久保存；不支持时会明确提示只载入本次页面。使用“资料管理”备份全部行业资料，可迁移至其他电脑。

浏览器导入不会自动修改工程文件或共享站点。要更新随页面交付的内置资料，使用下方重建流程。浏览器本地备份和共享发布分别处理。

## 表格约定

- 两层地区表头：上层区域、下层国家。
- 固定含义列：子行业、头部客户、全球设厂／产能及市场布局、承接主体及服务业务、信息来源。
- 按表头识别列，国家增减不依赖固定列号。
- 客户合并行中的来源逐行读取，保留真实超链接和引用编号。
- 地区格的首行是项目名，括号中使用官方业务类型，后续行描述项目。
- 一个格内有多个项目时用空行分段。
- 横向合并按区域项目读取，相同客户相同区域的重复合并段合并展示。
- C列是经营布局背景，不自动增加物流项目。没有官方类型标签的项目不被强制分类，制造配套单独标记。
- D列按“主体：地域／项目，具体服务。[来源编号]”书写。程序依据项目、地域、服务功能和来源关联主体，不将全部合作方分摊给各国。

## 重建内置页面

需要Node.js和Python 3。组件已随工程保存，无需安装依赖。

1. 将更新后的行业表格放入 `input/`。
2. 执行 `node refresh-data.cjs "input/表格名称.xlsx" "行业名称"`，仅替换对应行业。
3. 执行 `python3 build.py`。
4. 分发生成的 `index.html`，或发布本目录。

例如：`node refresh-data.cjs "input/国际业务热力图_汽车_全球布局版.xlsx" "汽车"`。网页导入与重建调用同一个 `workbook-core.js`，避免形成两套读取逻辑。

## 核心文件

- `index.html`：包含依赖及内置数据的离线单文件。
- `page.html`、`style.css`、`app.js`：页面、样式和交互。
- `workbook-core.js`：模板读取、分类、主体关联、地域与去重。
- `refresh-data.cjs`、`build.py`：读取工作簿并打包。
- `data.json`、`metadata.json`、`regions.json`：六个行业数据集、国家元数据和区域定义。
- `input/`：六个行业工作簿源。
- `vendor/`：D3、TopoJSON、world-atlas、SheetJS及许可。

## 组件

D3 7.9.0、TopoJSON Client 3.1.0、world-atlas 2.0.2、SheetJS CE 0.20.3。许可见 `vendor/`。SheetJS来源：https://docs.sheetjs.com/docs/getting-started/installation/standalone/ 。

切换行业时清空客户、业务、区域、国家和搜索条件，返回该行业全球总览。“清除选项 · 返回首页”保留当前行业。六行业版使用独立的浏览器保存空间，不覆盖先前各独立页面。备份导出包含当前全部行业。

医药及餐饮保留表格中的国家、区域和全球服务层级。仅有全球承接信息的客户，不生成国家项目或区域热度；原始表格空白保持为空。客户布局摘要、承接主体及来源均从工作簿读取。

案例承接关系无法直接对应国家时，详情内展示“客户承接主体汇总”，保留D列原有服务地域和来源，不把企业级合作关系改写成该国家的承接合同。运营计划表述不自动标记为规划建设项目。
